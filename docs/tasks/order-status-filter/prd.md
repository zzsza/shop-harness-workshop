# order-status-filter

확정 여부: **확정**

고객이 내 주문 목록을 상태별로 걸러 본다.
이슈: `docs/issues/3.md`

## 문제 / 범위

주문이 많은 고객은 배송중인 주문 하나를 찾으려고 목록 전체를 훑는다.

- 목록 API가 `status` 쿼리를 받아 그 상태인 내 주문만 준다.
- 내 주문 목록 위에 상태 필터(전체, 결제완료, 배송준비, 배송중, 배송완료, 주문취소)가 있고, 고른 필터는 주소(`/orders?status=shipping`)에 남는다.

## 비범위 / 보존 동작

- 여러 상태를 한 번에 고르기, 기간·검색 필터, 페이지 나누기는 없다.
- `status`가 없으면 지금과 같은 응답(내 주문 전부, 최신순)이다.
- 남의 주문은 어떤 필터로도 보이지 않는다.

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 필터는 서버가 한다. 화면은 받은 목록을 그대로 보인다 | 이슈의 API 약속 |
| D-2 | 없는 상태 값은 400 `VALIDATION_FAILED`, 화면 주소의 없는 상태 값은 찾을 수 없는 화면 | 이슈의 API 약속, 잘못된 값을 조용히 넘기지 않는다 |
| D-3 | 고객은 세션에서만 정한다 | `docs/rules/05-customer-id-from-session.md` |

## 완료 조건

| ID | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | `GET /api/orders?status=paid`는 내 결제완료 주문만 최신순으로 준다 | 테스트: API 통합 |
| AC-2 | `status`가 없으면 내 주문 전부를 최신순으로 준다 | 테스트: API 통합(기존 목록 테스트도 그대로 통과) |
| AC-3 | 없는 상태 값은 400 `VALIDATION_FAILED`다 | 테스트: API 통합 |
| AC-4 | 다른 고객의 주문은 같은 상태여도 나오지 않는다 | 테스트: API 통합 |
| AC-5 | 필터를 누르면 그 상태로 다시 불러오고 주소에 `?status=`가 남는다. 머리글이 "배송중 N건"이 된다 | 테스트: 컴포넌트 |
| AC-6 | 고른 상태의 주문이 없으면 "배송중 주문이 없어요"와 전체 보기 버튼이 보인다 | 테스트: 컴포넌트 |
