# free-shipping-50000

확정 여부: **확정**

무료배송 기준을 3만 원에서 5만 원으로 올린다. 배송비 3,000원은 그대로다.
이슈: `docs/issues/5.md`
상태: **승인 대기**. 구현이 `apps/api/src/orders/domain/shipping-fee.ts`를 고치려는 자리에서 배송비 경로 승인을 기다린다.

## 문제 / 범위

- `FREE_SHIPPING_THRESHOLD`를 `won(50_000)`으로 바꾼다. 견적·주문·배송 안내(`/api/shipping-policy`)가 모두 이 상수를 쓰므로 고객센터와 상품 상세 문구도 함께 바뀐다.

## 비범위 / 보존 동작

- 이미 만든 주문의 저장된 배송비는 그대로다.
- 배송비 3,000원은 그대로다.

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 바꾸는 곳은 상수 하나다. 화면 문구는 `/api/shipping-policy`에서 오므로 따로 고치지 않는다 | `docs/shipping-fee-rule.md` |
| D-2 | 기준이 바뀌어 달라지는 기존 테스트 기대값은 이 PRD의 완료 조건에서 새 값을 가져온다 | `docs/rules/07-verify-and-fixed-expectations.md` |
| D-3 | 배송비 경로를 고치는 일은 사람이 승인한다 | 실습 3의 위험 경로 승인(`permissions.ask`) |

## 완료 조건

| ID | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | 상품 합계 49,999원 이하 견적은 배송비 3,000원, 50,000원 이상은 0원이다 | 테스트: API 통합 |
| AC-2 | `/api/shipping-policy`의 `freeThreshold`가 50,000이고 고객센터 배송 안내가 "50,000원 이상 주문하면 무료"다 | 테스트: API 통합과 컴포넌트 |

## 질문

미해결 질문 없음. 승인을 받으면 구현을 이어 간다.
