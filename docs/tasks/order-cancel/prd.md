# order-cancel

확정 여부: **확정**

고객이 결제완료·배송준비 상태의 내 주문을 취소하고, 주문한 재고가 되돌아온다.
인터뷰 기록: `docs/tasks/order-cancel/interview.md`

## 문제 / 범위

지금은 주문을 만든 뒤 고객이 취소할 방법이 없다. 잘못 주문하면 관리자에게 따로 부탁해야 하고, 재고는 되돌릴 길이 없다.

- 고객은 내 주문 상세에서 "주문 취소" 버튼을 눌러, 확인 창을 거쳐 주문 전체를 취소한다(`POST /api/orders/:orderId/cancel`).
- 취소한 주문의 상태는 `cancelled`("주문취소")이고, 주문 품목 수량만큼 재고가 늘어난다.
- 재고가 늘 때마다 입출고 이력에 "취소 복구" 한 줄이 주문 번호와 함께 남는다.
- 주문 응답은 취소할 수 있는지(`cancellable`)를 서버가 계산해 담는다.
- 관리자 주문 목록과 상세는 취소된 주문을 뱃지로 보이고 다음 단계 버튼을 보이지 않는다.

## 비범위

- 부분 환불(품목·수량 일부만 취소하고 그만큼 돌려주기). 다음 작업으로 넘긴다.
- 관리자가 고객 대신 취소하는 기능, 취소 사유 입력.
- 실제 환불, 쿠폰·포인트 되돌리기(이 레포에 없다).
- 배송이 시작된 주문의 반품·교환.

## 보존 동작

- 주문 생성·견적·재고 차감·입고의 동작과 금액은 그대로다.
- 관리자 상태 변경(`POST /api/admin/orders/:orderId/status`)은 지금처럼 다음 단계로만 넘긴다.
- 남의 주문은 지금처럼 찾을 수 없다고 나온다(404).
- 주문 응답의 기존 필드는 바뀌지 않는다. `cancellable`만 더한다.
- 기존 테스트의 기대값은 바꾸지 않고 `npm run verify`가 통과한다.

## 결정

| ID | 결정 | 근거 |
| --- | --- | --- |
| D-1 | 주문 전체 취소만 한다. 부분 환불은 하지 않는다 | `interview.md` D-1 |
| D-2 | 취소할 수 있는 상태는 `paid`(결제완료)와 `preparing`(배송준비)뿐이다. 그 밖에서 요청하면 409 `ORDER_NOT_CANCELLABLE`이다 | `interview.md` D-2 |
| D-3 | 주문한 고객 본인만 취소한다. 고객은 세션에서만 정한다. 관리자 계정은 403이다 | `interview.md` D-3, `docs/rules/05-customer-id-from-session.md` |
| D-4 | 재고 복구는 `InventoryService`의 새 메서드로만 한다. 상태 변경과 재고 복구는 한 트랜잭션이다 | `interview.md` D-4, `docs/rules/01-inventory-service-only.md` |
| D-5 | 입출고 이력에 `restock`(취소 복구) 종류를 더한다. 기존 `CHECK` 제약을 넓히려고 새 번호 마이그레이션 `0002`를 쓴다 | `docs/rules/08-new-numbered-migration.md` |
| D-6 | 이미 취소된 주문을 다시 취소하면 200으로 같은 주문을 돌려주고 재고는 다시 늘리지 않는다 | `interview.md` D-5 |
| D-7 | `cancelled`로의 전이는 orders 도메인의 전이 함수 한 곳이 정한다. 관리자 상태 변경으로는 갈 수 없다 | `interview.md` D-9, `docs/rules/03-order-status-transition.md` |
| D-8 | `cancellable`은 서버가 계산해 응답에 담고 화면은 그대로 쓴다 | `docs/rules/06-dto-in-web-mapper.md` |
| D-9 | 화면은 확인 창을 거치고, 취소된 주문에 "교육용 가상 결제라 실제 환불은 없어요"를 보인다 | `interview.md` D-6, D-7 |

지금 코드에서 본 사실은 `interview.md`의 "지금 동작"에 있다.

## 완료 기준

| AC | 상황·입력 → 행동 → 관찰할 결과 | 확인 방법 |
| --- | --- | --- |
| AC-1 | 결제완료 주문을 주문한 고객이 취소하면 200이고 `status: "cancelled"`, `cancellable: false`이며, 품목마다 재고가 주문 수량만큼 되돌아온다 | 테스트: API 통합(`tests/order-cancel.test.ts`) |
| AC-2 | 취소하면 품목마다 입출고 이력에 `restock` 한 줄(늘어난 수량, 주문 번호)이 남는다 | 테스트: API 통합 |
| AC-3 | 배송준비 주문도 취소되고 재고가 되돌아온다 | 테스트: API 통합 |
| AC-4 | 배송이 시작된 주문(배송중·배송완료)을 취소하면 409 `ORDER_NOT_CANCELLABLE`이고 주문 상태와 재고는 그대로다 | 테스트: API 통합 |
| AC-5 | 이미 취소된 주문을 다시 취소하면 200이고, 재고는 한 번만 늘고 `restock` 이력도 한 줄뿐이다 | 테스트: API 통합 |
| AC-6 | 남의 주문을 취소하면 404, 로그인하지 않으면 401, 관리자 계정은 403이고 주문과 재고는 그대로다 | 테스트: API 통합 |
| AC-7 | 관리자가 상태 변경으로 `cancelled`를 보내면 409 `INVALID_STATUS_TRANSITION`이고 주문과 재고는 그대로다 | 테스트: API 통합 |
| AC-8 | 주문 조회 응답의 `cancellable`은 결제완료·배송준비면 true, 배송중·배송완료면 false다 | 테스트: API 통합 |
| AC-9 | 고객이 결제완료 주문 상세에서 "주문 취소" → 확인 창의 "주문 취소하기"를 누르면 상태가 "주문취소"로 바뀌고 버튼이 사라지며 "실제 환불은 없어요" 안내가 보인다 | 화면 확인: `customer1@grabmarket.test`로 로그인 → 상품 하나를 주문 → 내 주문 상세 → "주문 취소" → 확인 창 → "주문 취소하기" → 제목의 "주문취소"와 안내를 찍는다 |
| AC-10 | 취소할 수 없는 주문(배송중)의 상세에는 "주문 취소" 버튼이 없다 | 테스트: 컴포넌트 |
| AC-11 | 확인 창에서 "돌아가기"를 누르면 취소 요청 없이 창이 닫히고 주문은 그대로다 | 테스트: 컴포넌트 |
| AC-12 | 취소 요청이 실패하면 이유가 화면에 보이고 주문은 그대로 보인다. 그 사이 배송이 시작돼 거절되면 이유를 보이고 최신 상태로 바뀐다 | 테스트: 컴포넌트 |
| AC-13 | 취소된 주문은 관리자 주문 목록·상세에서 "주문취소" 뱃지로 보이고 다음 단계 버튼이 없으며, 다음 단계로 넘기려 하면 409다 | 테스트: 컴포넌트와 API 통합 |
| AC-14 | 관리자 재고 화면에서 취소된 주문의 상품을 열면 입출고 이력에 "취소 복구 · 주문 <번호>" 줄이 늘어난 수량(+)으로 보인다 | 화면 확인: AC-9에서 취소한 뒤 `admin@grabmarket.test`로 로그인 → 재고 → 그 상품 → 입출고 이력의 "취소 복구" 줄을 찍는다 |
| AC-15 | `0002` 마이그레이션이 `0001`만 적용된 DB에 적용되고, 기존 이력 행은 그대로 남으며 `restock`은 받고 다른 종류는 거절한다 | 테스트: `packages/db/src/migrate.test.ts` |
