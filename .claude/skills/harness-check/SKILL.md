# 하네스 점검

요청: $ARGUMENTS

사용자에게 하는 말은 사용자가 쓰는 언어로 한다. 한국어로 물으면 한국어로 답한다.
읽기만 한다. 레포와 설정 파일은 고치지 않고, 결과는 `~/.harness-check/<레포 이름>/<시각>/`에만 쓴다.
점검표는 `${CLAUDE_SKILL_DIR}/references/checklist.md` 하나다. 여덟 영역, 영역마다 「있어야 할 것」과 「조심할 습관」이 있다.

```
0 후보 찾기 → 1 묻기 → 2 스캔(스크립트, 몇 초) → 3 점검 담당들에게 동시에 → 4 합치기(스크립트) → 5 보여 주기
```

## 0. 점검할 프로젝트 후보 찾기

이 점검은 보통 `npm run claude`(실습 계정 `~/.claude-workshop`)로 띄운 Claude Code에서 돈다.
실습 계정과 이 레포에는 수강생 자신의 하네스와 기록이 없다. 그래서 평소 계정(`~/.claude`)에서 평소 일하는 프로젝트를 찾아 고르게 한다.
레포 루트에서 실행한다.

```
node "${CLAUDE_SKILL_DIR}/scripts/projects.mjs" --exclude .
```

표준 출력은 JSON 한 줄이다: `configDir`(평소 설정 폴더)와 `candidates`(최근 90일에 평소 계정으로 Claude Code를 많이 쓴 git 프로젝트, 많이 쓴 순).
세션 내용은 열지 않고 폴더 경로와 세션 수만 센다.
실패하면 오류를 한 줄 보여 주고, 후보 없이 이 레포를 점검한다.

## 1. 먼저 묻기

첫 줄로 할 일을 말한다: "고른 프로젝트와 Claude Code 설정을 읽기만 하고, 빈 곳과 손볼 곳을 지도로 보여 드릴게요."

요청에 이미 답이 있으면 그 질문은 건너뛴다.
남은 질문은 `AskUserQuestion` **한 번**에 묶어 묻는다. 탐색을 시작한 뒤에는 더 묻지 않는다.

| 질문 | 선택지 | 스캔 인자 |
|---|---|---|
| 어느 프로젝트를 점검할까요? | 후보 앞의 셋(이름, 설명은 경로와 마지막 사용일) / 이 실습 레포. 사용자가 다른 경로를 적어도 된다 | 아래 표 |
| 고른 프로젝트의 최근 30일 세션 기록에서 사용 습관을 세어도 될까요? 내 메시지의 개수와 반복만 세고 내용은 옮기지 않습니다. | 예 / 아니오 | `--sessions yes·no` |
| 요즘 에이전트를 쓰며 가장 불편한 것은? | 결과가 들쭉날쭉하다 / 계속 지켜봐야 한다 / 검증을 내가 다 한다 / 매번 설명을 다시 한다 | `--pain "<답 그대로>"` |

후보가 없으면 프로젝트 질문은 빼고 이 레포를 점검한다. 요청에 프로젝트 경로가 있으면 그 경로를 쓴다.
질문 도구를 쓸 수 없는 실행(비대화형)이면 묻지 않고 이 레포, `no`, 빈 글로 간다.

| 고른 것 | `--repo` | `--config` |
|---|---|---|
| 후보나 사용자가 적은 경로 | 그 경로 | `configDir`(평소 계정. 그 프로젝트에서 실제로 쓰는 설정) |
| 이 실습 레포 | `.` | 넣지 않는다(지금 띄운 실습 계정) |

다른 프로젝트를 고르면 점검 담당이 그 폴더의 파일을 읽을 때 Claude Code가 허락을 물을 수 있다.
스캔 전에 "다른 폴더를 읽기만 하니, 읽기 허락을 물으면 허락해 주세요."라고 한 줄 알린다.

## 2. 스캔

레포 루트에서 실행한다. `--repo`와 `--config`는 1의 표대로 넣는다.

```
node "${CLAUDE_SKILL_DIR}/scripts/scan.mjs" --repo "<폴더>" [--config "<configDir>"] --sessions <yes|no> --pain "<불편>"
```

표준 출력은 JSON 한 줄이다.
`out`(결과 폴더)과 `briefs`(점검 담당에게 넘길 일, `g1`·`g2`·`g3`)를 기억한다.
실패하면 오류 메시지를 그대로 보여 주고 멈춘다.

## 3. 점검 담당들에게 동시에 맡기기

`briefs`에 들어 있는 묶음(최대 셋)마다 `harness-inspector` 에이전트를 하나씩 띄운다.
여러 개를 **한 메시지에서 동시에** 띄운다. 하나씩 기다리지 않는다.
프롬프트에는 다음 두 가지만 넣는다.

- `맡은 묶음: <g1>`, `레포: <briefs.<g1>.repoRoot>`
- 그 묶음의 브리프 JSON 전체를 그대로

담당은 마지막에 JSON 블록 하나를 돌려준다. 담당이 끝나면 결과가 돌아오므로 `sleep` 같은 명령으로 기다리지 않는다.
담당이 실패하거나 JSON이 깨지면 그 묶음은 빼고 진행한다. 다시 띄우지 않는다. 보고서가 그 항목을 「확인 못 함」으로 표시한다.
`briefs`가 비었으면 이 단계를 건너뛴다.

## 4. 합치기

담당이 돌려준 JSON을 묶음별로 모아 `<out>/parts.json`에 쓴다.

```json
{ "g1": { "results": [ ... ] }, "g2": { "results": [ ... ] } }
```

그다음 보고서를 만들고 연다.

```
node "${CLAUDE_SKILL_DIR}/scripts/report.mjs" --out "<out>" --open
```

## 5. 보여 주기

대화창에는 다섯 줄 안으로 쓴다.

1. 한 줄 진단(`headline`)과 켜진 불(`lit`)
2. 손볼 곳(`warning`이 있으면 그대로, 무엇인지 한두 개). 「잘못」 같은 탓하는 말 대신 「손볼 곳」이라고 쓴다
3. 다음에 해 볼 3개: 항목, 영역, 첫걸음
4. 보고서 경로(`html`), 열리지 않았으면 직접 열라고
5. 같은 레포를 같은 설정 폴더로 다시 돌리면 이번 결과와 비교한다는 한 줄 (`compared`가 있으면 전후 채움을 대신 쓴다)

`problems`가 비어 있지 않으면 쓰지 못한 담당 결과가 있다고 한 줄 덧붙인다.
사용자가 고쳐 달라고 하기 전에는 아무것도 고치지 않는다.
